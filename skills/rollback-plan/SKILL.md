# Rollback Plan
## 절차
1. Rollback Trigger를 수치/현상 기준으로 정의한다.
2. 되돌릴 Application/Config/Data 범위를 구분한다.
3. 변경 후 생성된 데이터의 처리 방식을 정의한다.
4. 원복 순서와 의존성을 확인한다.
5. 원복 후 정상성 검증 항목을 정의한다.
6. 최대 의사결정 시점과 승인권자를 정의한다.
## 원칙
원복 가능 여부를 배포 당일 처음 검토하지 않는다.
